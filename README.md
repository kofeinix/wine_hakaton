# Сканер вин

Веб-сервис, который находит российское вино по фотографии бутылки или этикетки. Пользователь
фотографирует вино в магазине или ресторане и получает карточку: производитель, регион, сорт,
крепость, температура подачи, сочетания с блюдами, отзывы и похожие вина. Каталог — 2107 вин
портала «Своё Вино».

## Как это работает

```
фото ─► детекция бутылки и этикетки (YOLO)
     ─► эмбеддинги трёх ракурсов: всё фото, бутылка, этикетка (SigLIP2-384 + дообученный адаптер)
     ─► поиск похожих фото в каталоге (Qdrant, ~23 тыс. фото)  ─┐
     ─► распознавание текста этикетки (vision-LLM Qwen3-VL)   ─┴► реранк ─► результат
```

1. **Кропы.** YOLO находит на фото бутылку и этикетку. Если в кадре полка с несколькими винами,
   пользователь может нажать на нужную этикетку или обвести бутылку рамкой.
2. **Визуальный поиск.** Для каждого ракурса считается эмбеддинг SigLIP2 и ищутся ближайшие фото
   каталога. Каталог дополнен сгенерированными ракурсами (бутылка в разных сценах и при разном свете),
   поэтому поиск устойчив к фону и освещению. Скоры фото агрегируются в скор вина.
   Поверх SigLIP2 — свой адаптер векторов (`scripts/train_view_adapter.py`): обучен на каталоге сводить
   фото «из жизни» с фото того же вина и разводить соседние вина одной линейки. На отложенных фото
   Vivino он поднял точность поиска с 88,8% до 92,9% (top-1, вместе с распознаванием текста).
3. **Текст этикетки.** Vision-LLM читает этикетку; найденные производитель, название, сорт, цвет,
   сахар и крепость уточняют порядок кандидатов. Если визуальный результат и так уверенный,
   распознавание пропускается. Без LLM сервис работает — только по изображению.
4. **Результат.** Лучшее совпадение с карточкой вина, похожие варианты и диагностика поиска
   (рамки детекции, время этапов, разложение скора).

Во вкладке «Сомелье» — подбор без нейросети: для чего вино, что на столе и каким оно должно быть, фильтры каталога (тип, цвет,
сахар, регион, сорт, рейтинг), поиск по названию с исправлением опечаток и список вин по регионам.
У каждого вина в подборке указано, почему оно подошло, — по полям его карточки.

Винные термины в названии и описании вина подчёркнуты: по нажатию справа снизу открывается
чат-справочник с определением. В нём же есть поиск по словарю (140 терминов, источник —
[словарь винных терминов Luding](https://luding-group.ru/slovar-vinnykh-terminov/)).

Для пользователей есть кабинет: история сканирований (без входа — временная, после входа
сохраняется в аккаунт), избранное, оценки с комментариями и напоминания «вы недавно смотрели
вина — что-то взяли?».

**Стек:** Nuxt (Vue) · FastAPI · PostgreSQL · Qdrant · MinIO · Redis · YOLO · SigLIP2 · Qwen3-VL.

## Запуск

### Что нужно

- Docker с Docker Compose v2 (Docker Desktop на macOS/Windows);
- ~15 ГБ свободного места, для Docker — от 8 ГБ памяти;
- интернет при первом запуске: скачиваются модели (~1,7 ГБ) и данные (~5,2 ГБ);
- по желанию — [LM Studio](https://lmstudio.ai) или [Ollama](https://ollama.com) для распознавания текста.

### Шаги

```bash
git clone https://github.com/kofeinix/wine_hakaton.git
cd wine_hakaton
cp .env.example .env
docker compose up -d --build
```

Первый запуск занимает время: сервисы `models-init` и `data-init` скачивают модели и данные, затем
заполняются база, Qdrant и хранилище фото. Следить за прогрессом:

```bash
docker compose logs -f models-init data-init qdrant-init minio-init app
```

Когда в логах `app` появится `Uvicorn running`, откройте:

- **сайт:** http://localhost:5173
- **API (Swagger):** http://localhost:8000/docs

При следующих запусках всё уже скачано и загружено — сервис стартует за минуту.

### Распознавание текста этикеток (по желанию)

Запустите локальную модель Qwen3-VL-4B одним из способов:

```bash
./run_llm.sh            # LM Studio (macOS / Linux)
./run_llm.sh ollama     # Ollama
./run_llm.sh vllm       # Linux с NVIDIA GPU
```

На Windows: `.\run_llm.ps1` или `.\run_llm.ps1 ollama`.

Скрипт скачает модель, запустит сервер и выведет две строки для `.env` (`LLM__BASE_URL`,
`LLM__MODEL_NAME`). Для LM Studio значения по умолчанию уже подходят. После изменения `.env`:

```bash
docker compose up -d app
```

### Проверочный скрипт организаторов

Сервис сразу отвечает на адрес, который скрипт использует по умолчанию —
`POST http://127.0.0.1:8080/v1/eval/predict` (порт задаётся `EVAL_PORT` в `.env`):

```bash
cd eval
bash participant_test.sh --images-dir ./queries --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' --output ./predictions.jsonl
```

Ответ — `{"slug": "..."}`, в историю поиска такие запросы не пишутся. Скрипт ждёт ответ не дольше
10 секунд, поэтому распознавание текста ограничено `SEARCH__OCR_BUDGET_SECONDS` (7,5 с): если LLM не
успела, сервис отвечает по изображению. Модели прогреваются при старте, первый запрос не ждёт их загрузки.

## Дообучение: адаптер векторов SigLIP2

SigLIP2 обучен на общих картинках: фото бутылки «из жизни» (полка, руки, свет) и фото того же вина
в каталоге он считает недостаточно похожими, а соседние вина одной линейки — слишком похожими. Вместо
дообучения всей модели мы учим небольшой адаптер поверх её векторов — `f(x) = normalize(x + B·A·x)`,
ранг 64, свой для каждого ракурса (всё фото, бутылка, этикетка). Он применяется одинаково к фото каталога
(при загрузке в Qdrant) и к запросу; файл весит 1 МБ и лежит в репозитории: `models/adapter/siglip2_384_views.npz`.

**Данные** — эмбеддинги фото каталога, метка — только `wine_id`, ручной разметки нет:

| источник | фото (всё фото / бутылка / этикетка) | роль |
|---|---|---|
| главное фото с портала | 2107 / 1921 / 2047 | позитив |
| сгенерированные сцены (полка, стол, в руках × 3 света) | 18963 / 18867 / 18227 | якорь и позитив |
| фото с Яндекса | 2379 / 1883 / 2101 | якорь и позитив |
| фото пользователей Vivino (`data/eval`) | 537 / 406 / 482 | якорь и позитив; при проверке — отложены |

Пара «якорь — позитив» — два разных фото одного вина; негативы — остальные вина батча, а батч собирается
из похожих вин (случайное вино + его ближайшие соседи по индексу), чтобы учиться различать вина одной линейки.
Функция потерь — симметричный InfoNCE. Картинки, совпадающие с фото другого вина (косинус > 0,98), выброшены.

**Проверка.** Адаптер обучен без фото Vivino, на них — top-1 ближайшего фото каталога по ракурсу:

| ракурс | SigLIP2-384 | + адаптер |
|---|---|---|
| всё фото | 64,2% | 81,6% |
| бутылка | 70,0% | 85,2% |
| этикетка | 84,6% | 91,3% |

Весь поиск (ракурсы, агрегация, распознавание текста) на тех же 537 фото, адаптер без них в обучении:

| вариант | только изображение | с текстом этикетки |
|---|---|---|
| SigLIP2-224 (было) | 81,9% | 88,8% |
| SigLIP2-384 | 84,9% | 89,2% |
| SigLIP2-384 + адаптер | 91,2% | 92,9% |

Итоговый адаптер обучен на всех фото, вместе с Vivino. Воспроизвести (около минуты на CPU):

```bash
python scripts/index_siglip2_views_qdrant.py --model-dir models/siglip2_384 \
  --output-dir data/embeddings/siglip2_384 --collection-encoder siglip2_384   # эмбеддинги каталога, ~35 мин на Apple M4
python scripts/train_view_adapter.py                                          # проверка + финальный адаптер
docker compose up -d --build                                                  # коллекции с новой версией адаптера
```

## Если что-то пошло не так

- **Порт занят.** Поменяйте нужный порт в `.env` (`APP_PORT`, `FRONTEND_PORT`, `DATABASE__PORT`,
  `QDRANT__PORT`, `MINIO__PORT`, `REDIS__PORT`) и выполните `docker compose up -d`.
- **Данные не скачались.** Скачайте вручную из [папки на Яндекс Диске](https://disk.yandex.ru/d/TW3su5DtKTNtfQ)
  и положите: `siglip2_384_original.npz`, `siglip2_384_bottle_crop.npz`, `siglip2_384_label_crop.npz` —
  в `data/embeddings/siglip2_384/` под именами `original.npz`, `bottle_crop.npz`, `label_crop.npz`,
  `photos.tar.gz` и `photos_webp.tar.gz` (главные фото в webp, необязательный) — в `data/`.
  Затем `docker compose up -d`.
- **Модели не скачались.** Повторите `docker compose up models-init` и посмотрите его лог.
- **Текст этикетки не распознаётся** (в диагностике «OCR не применён»). Проверьте, что LLM запущена
  и её адрес в `.env` верный; без LLM поиск продолжает работать по изображению.
- **Начать с нуля:** `docker compose down -v` удалит базу, векторы и фото (скачанные файлы в `data/`
  и `models/` останутся), затем `docker compose up -d`.

## Структура репозитория

```
frontend/          сайт (Nuxt)
src/               API: поиск, пользователи, работа с моделями и хранилищами
scripts/           подготовка данных и инициализация сервисов
data/db/           каталог вин (JSON) — загружается в PostgreSQL при старте
models/yolo/       своя модель детекции этикеток (остальные модели скачиваются)
models/adapter/    дообученный адаптер векторов SigLIP2 (scripts/train_view_adapter.py)
run_llm.sh / .ps1  запуск локальной vision-LLM
```

Скрипты в `scripts/`, которыми собраны данные (для воспроизведения):

| Скрипт | Что делает |
|---|---|
| `prepare_image_views.py` | вырезает бутылку и этикетку на фото каталога |
| `generate_qwen_image_edit_views.py`, `generate_flux2_klein_views.py` | генерируют дополнительные ракурсы бутылок |
| `index_siglip2_views_qdrant.py` | считает эмбеддинги SigLIP2 фото каталога по ракурсам (`--model-dir models/siglip2_384 --output-dir data/embeddings/siglip2_384`) |
| `train_view_adapter.py` | обучает адаптер векторов на эмбеддингах каталога, с проверкой на отложенных фото Vivino |
| `download_main_webp.py` | скачивает главные фото вин в webp (прозрачный фон) с сайта портала |
| `build_photos_archive.py` | собирает архив фото для MinIO (`--webp` — отдельный архив webp) |
| `enrich_wines_from_site.py` и др. `enrich_*` | дополняют карточки вин данными портала |
| `import_wine_terms.py` | собирает словарь винных терминов в `data/db/wine_terms.json` |
| `eval_search.py` | оценка качества поиска на отложенной выборке фото |
| `init_database.py`, `init_qdrant.py`, `prepare_models.py`, `download_data.py` | запуск (вызываются из Docker Compose) |
