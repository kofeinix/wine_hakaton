# OCR lab

Офлайн-эксперименты с OCR-реранком на сохранённых ответах API — без повторных запросов к LLM.

## Данные

`scripts/eval_search.py` сохраняет полные ответы API в `data/eval_responses_<eval-папка>.json`
(OCR-текст, пул кандидатов с визуальным скором **до** OCR-реранка). Старый дамп
`data/ocr_visual_grid_responses.json` тоже поддерживается (визуальный скор ≈ `max_score`).

```bash
uv run python scripts/eval_search.py --stages global          # -> data/eval_responses_eval.json
export OCR_LAB_RESPONSES=data/eval_responses_eval.json        # датасет для экспериментов
```

Карточки вин берутся из `data/db/*.json`.

## Проверить продовую формулу

```bash
uv run python scripts/ocr_lab/eval_formula.py --responses $OCR_LAB_RESPONSES --show-changes
```

Считает `final = visual + ocr_bonus` **продовым** модулем `src/ml/ocr_matching.py` и печатает
Acc@1 / MRR / R@5 без и с OCR, а также фото, где OCR исправил или сломал top-1.

## Эксперименты

```bash
uv run python scripts/ocr_lab/experiments.py prepare   # признаки (~20 с), кеш в data/ocr_lab_cache/
uv run python scripts/ocr_lab/experiments.py matchers  # 7 алгоритмов сопоставления сущностей
uv run python scripts/ocr_lab/experiments.py formula   # формулы с "уникальными доказательствами"
uv run python scripts/ocr_lab/experiments.py catboost  # CatBoost с нуля и поверх формулы
uv run python scripts/ocr_lab/experiments.py errors    # разбор ошибок и потолок OCR
```

Веса подбираются только на обучающих фолдах (5-fold, группировка по вину, несколько разбиений),
метрики — на отложенных. На ~500 фото разница ±0.3 п.п. — шум.

| Модуль | Что делает |
|---|---|
| `lab_data.py` | загрузка ответов API и каталога, построение продовых `OcrCatalog` / `OcrCandidate` |
| `lab_features.py` | признаки для всех пар (фото, кандидат): 7 матчеров × с/без транслитерации OCR, противоречия |
| `lab_tokens.py` | сходство каждого слова карточки с OCR (для "уникальных доказательств") |
| `lab_eval.py` | метрики, параметрическая формула, подбор весов, CV |
| `lab_spec.py`, `lab_bm25.py` | "уникальные доказательства" (IDF по пулу) и BM25-вариант |

## Результаты (578 фото из data/eval, старый дамп)

| Вариант | CV Acc@1 | MRR |
|---|---|---|
| только изображение | 79.4% | 0.876 |
| прежняя формула 0.8·visual + 0.2·ocr | 86.2% | 0.922 |
| любой из 7 матчеров (window, coverage, IDF, partial…) | 85.9–86.5% | ~0.923 |
| BM25 (OCR = запрос, карточки = документы) | 85.3–85.9% | ~0.918 |
| **IDF-coverage + уникальные доказательства** (прод) | **87.4% ± 0.2** | **0.930** |
| CatBoost с нуля | 81–82% | ~0.90 |
| CatBoost поверх формулы (baseline) | ≈ формула | ~0.935 |

Выводы:

1. Способ сравнения сущности почти не важен — все матчеры в пределах шума. Транслитерация OCR
   на этом наборе нейтральна (оставлена для латинских этикеток).
2. Все ошибки — вина **того же производителя**. Доля названия в OCR систематически выбирает
   более короткое название линейки («Syrah Katya» вместо «Syrah Katya Belmas»); "уникальные
   доказательства" (редкое среди кандидатов слово, найденное в OCR) это исправляют.
3. Удалять слова цвета/сахара из названия нельзя: именно они отличают вина линейки
   («Кокур десертный» / «Кокур сухое») — проверено, минус 2 фото.
4. После новой формулы из 68 ошибок в 61 в OCR нет ни одного слова в пользу правильного вина
   (дубликаты / почти одинаковые карточки в БД) — потолок OCR на этом наборе.
